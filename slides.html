Capybarrier

An adaptive immune system for AI agents

Agents in production read untrusted text all day, and then they move money and send email.

  • New attacks arrive every week, and static guardrails go stale.
  • Fixes are prompts edited by hand after an incident.
  • Nobody can prove a fix works, or that it didn't break normal users.

Our demo patient: Kapi, the concierge agent of CapySpa, a capybara hot spring resort. It books treatments, issues refunds and sends email.

Capybarrier  Statement 1, Recursive Harnessing

It learns from every attack, and ships a fix only with receipts

On every request

milliseconds to seconds, in production

  1. A guest message arrives, along with any untrusted tool data: booking memos, profile notes.
  2. Atlas Vector Search compares it with every known attack. A match is refused at the door, with no LLM call.
  3. Anything new goes to Kapi's LLM under the current harness: rules, playbooks, tool policy and context policy.
  4. Output guardrails check the reply before it leaves.

After every round of attacks

the harness rewrites itself

  1. Code detectors find the breaches: a leaked secret, data emailed out, a refund that shouldn't happen.
  2. An evolver proposes patches to Kapi's own rules, guardrails, tool access and context policy.
  3. Receipts: each patch replays every breach and every normal request.
  4. It ships only if it fixes breaches and breaks nothing. Attacks that got through become new fingerprints.

Honest by construction. The evolver trains with immune memory switched off, so it can't memorize its way out, and the held out attack families are never shown to it.

Capybarrier  Results

Built on MongoDB Atlas, and running live

The harness is data

One Atlas document per version, guarded by a strict $jsonSchema validator, so the database itself refuses a malformed self edit. $graphLookup traces the lineage.

Immune memory

Atlas Vector Search over Voyage embeddings from the Atlas Model API, filtered to the active version's fingerprints. A known attack costs one query, not an LLM call.

Production

Atlas Agent Engine hosts Kapi. The evolver itself ran there against the sandbox cluster, and every request loads the active harness, so a fix is live with no redeploy.

Raindrop closes the loop

Every request is an event with signals like runbook_block and breach. Flagged production requests flow back to the evolver through the Query API.

Every attack makes Kapi stronger.
